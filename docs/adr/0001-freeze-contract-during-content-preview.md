# 0001 — 内容预览期冻结契约，版本随确认后批量同步

- 状态：已接受（2026-09-22）
- 影响版本：5.0.0 → 5.1.0

## 背景

5.1.0 是一次内容基线改版：诊断主线五步、三个行动表达、人群口径与 README 结构调整，评分算法与字段结构不变。样稿需先经人工评审确认，才全面落地文档、示例与测试。若样稿期就把版本号升到 5.1.0，则 `scripts/version.py`、schema 的 `schema_version` const、SKILL.md metadata 与 `tests/test_version_contract.py` 必须同步改动；评审一旦否决，四处回滚，且仓库纪律「不修改冻结规则而不同步 schema、测试和版本号」会在未定稿状态下被反复触发，形成半成品契约。

## 决策

内容预览一律在最近一个已发布契约（当时为 5.0.0）上渲染，产物明确标注「5.1.0 预览（内容基线草案）」。版本号、schema const、SKILL.md metadata 与版本契约测试在样稿获用户确认后的**同一批次**内一次性同步到 5.1.0，同步动作本身构成一次完整、可测试的变更。

## 被否选项

- **样稿期即升版本**：三处同步成本提前支付；评审否决需回滚四处；预览与定稿之间出现多个中间版本状态，违背「同步是原子批次」的既有纪律。
- **预览不标注版本关系**：评审者无法区分「预览产物」与「正式 5.0.0 输出」，验收无法引用。

## 后果

- 预览产物中 `schema_version` / `rule_version` 字段仍为 5.0.0，属于**预期行为**，不是缺陷；判别预览产物的依据是预览标注，不是版本字段。
- 未来任何内容改版沿用此模式：预览不动契约，用户确认后批量升版。若某次改版确需先动算法，则不适用本模式，须按冻结规则变更流程单独处理。
