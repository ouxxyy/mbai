# 0003 — 对外文案采用 lieflat 白名单两步成稿

- 状态：已接受（2026-09-22）
- 影响版本：5.1.0 起的所有对外文案

## 背景

用户在样稿确认时提出硬约束：README 与 X 等对外文案要「说人话」，并指定以 `lieflat-less-ai-tone` skill 的白名单规则为唯一清理依据。该 skill 是白名单式改写器：只处理清单内规则、未命中文字逐字保留、结构不动、信息不增不减。直接一步写成「去 AI 味」文稿的问题在于没有对照基线，改动无法逐条追溯，容易越过 skill 边界重写观点或增删事实。

## 决策

对外文案（README、X 主帖与串帖，及后续同类公开文案）采用**两步成稿**：

1. 成稿成员先写直白成稿（内容、结构与事实在此定稿）；
2. 成稿成员完整读取 `lieflat-less-ai-tone/SKILL.md` 后，按白名单规则对直白稿做最小清理。

清理受三条硬边界约束：只处理清单内规则；未命中文字逐字保留；标题层级、段落、列表结构不动，事实与限定词不增不减不加重。每处改动须能对应 skill 规则编号，对应不上的撤销恢复原文。验收岗按该 skill 文末「最终验收」清单逐项核对。

## 被否选项

- **一步成稿**：无对照基线，无法逐处追溯改动依据，信息守恒无法验收。
- **不设此约束**：与用户对品牌语感（真诚、克制、不端着）的明确要求相悖。

## 后果

- 对外文案的改写自由度让位于可追溯性与事实保真；成稿比单步多一轮，验收增加对照成本。
- 估算标识、免责与限定表述（「估算，未经本地脚本校验」「不承诺」类）在清理中必须逐字保留，是信息守恒的重点核查对象。
- skill 白名单之外的风格特征（句长节奏、虚词密度、被动句、名词化、正文问句、句内排比等）实测不构成 AI 痕迹，明确不处理、验收时不扣分。
- 本约束只作用于对外文案；诊断内容、评分与报告正文的表达基线仍以 `references/content-baseline.md` 为准，两套基线不互相覆盖。
