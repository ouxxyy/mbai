# 0002 — 三个行动保留契约字段名、更换展示名

- 状态：已接受（2026-09-22）
- 影响版本：5.1.0

## 背景

5.1.0 把三个行动从三个并列建议收敛为一条路径：改造任务 → 练习关键判断 → 留下求职证据，与诊断主线五步的后三环逐字对齐。契约层面 `action_plan` 的字段名（`hand_to_ai` / `level_up` / `proof_7d`）是冻结项，改名需要同步 schema、迁移与测试；而 `action.title` 是自由文案字段（仅约束非空），展示名可以更换。旧展示名「交给 AI / 强化自己 / 拿出证据」与主线的路径语义脱节，安装版、复制提示语、X 文案三套交付物需要各自解释对应关系。

## 决策

- 契约字段名**保持不变**（`hand_to_ai` / `level_up` / `proof_7d`）。
- 展示名统一改为「**改造任务 / 练习关键判断 / 留下求职证据**」，渲染器固定标题、HTML 报告、分享卡、复制提示语与 X 文案一致使用新名；旧名在 5.1.0 内容中退役。
- 三个行动必须表达为同一条路径（先改造、再练判断、最后留证据），不得写成三个无关建议。
- 字段名 ↔ 展示名的映射长期保存在 `CONTEXT.md`。

## 被否选项

- **保留旧展示名**：与五步主线脱节，跨交付物要额外维护对应关系，且「行动是路径」这一核心改观在用户可见面上体现不出来。
- **契约字段名跟随新名**：违反「字段结构与评分公式不变」的版本约束，迁移逻辑复杂化，收益只在代码可读性。

## 后果

- 字段名与展示名长期存在词汇差（`hand_to_ai` ↔ 改造任务等），新贡献者需查 `CONTEXT.md` 映射表；这是接受的成本。
- 5.0.0 旧报告迁移时，原件中的旧展示名**原样保留**，不回写新名——迁移是无损的，旧建议不得冒充新版诊断。
